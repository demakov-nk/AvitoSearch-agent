# Агент умного поиска одежды на Авито

## Проблематика

Обычный поиск на Авито фильтрует объявления только по статическим характеристикам, которые продавец указал в форме: категория, город, цена, размер, бренд. Но реальные предпочтения покупателя так не задаются: «в хорошем состоянии» и «носилась аккуратно» фильтром не выразить, состояние вещи видно только по фото и описанию, а ответы на специфические вопросы — есть ли дефекты, какой материал, как продавец упаковывает — спрятаны в тексте объявления и в отзывах о продавце. Из-за этого пользователь вручную открывает десятки карточек и сам сопоставляет их со своими критериями. Агент решает эту рутину: получает запрос на естественном языке, формализует предпочтения в проверяемые критерии, ищет на Авито объявления о продаже одежды, целиком читает описания, характеристики, фото и отзывы о продавцах и выдаёт короткий обоснованный список.

## Постановка задачи

Задача агента — ускорить поиск одежды на Авито: взять на себя чтение и оценку объявлений по тем предпочтениям, которые нельзя задать фильтрами. Агент специализируется только на объявлениях о продаже одежды и ничего другого не ищет: на запросы вне этой категории он вежливо отвечает отказом и объясняет свою специализацию. На входе — запрос на естественном языке с обязательными и желательными критериями, например «зимняя куртка до 5 000 ₽, в хорошем состоянии, продавец с нормальными отзывами». На выходе — топ-3–5 объявлений со ссылками, сравнением по критериям и объяснением, почему каждое отобрано или отсеяно, а также ответы на специфические вопросы пользователя, найденные в описаниях и отзывах.

## Модель

Агент работает на **DeepSeek V4 Flash** через OpenAI-совместимый API, ключ хранится в `.env`. Другая модель подключается сменой `MODEL`/`BASE_URL` в том же файле.

## Как устроен (коротко)

Модель сама ничего не выполняет: она выбирает шаги, а код их исполняет. Цикл: история диалога → модель → (если нужно) вызов инструмента → результат в историю → повтор, пока модель не ответит. Лимит шагов — 10. Инструменты — функции Авито (`avito_search`, `avito_item`, `avito_seller_reviews`, `avito_health`), подключённые по протоколу MCP: сервер живёт отдельным процессом и сам ходит на сайт через Chrome. Память — история диалога за сессию. `skills/*.md` и `AGENTS.md` — инструкции, подкладываемые в системный промпт.

## Запуск

Нужны: Python 3.12+, Node.js 24+, Google Chrome, Poetry.

```bash
poetry install                                              # зависимости
# в .env укажи API_KEY (при необходимости — MODEL, AVITO_MCP_STATE_DIR)
AVITO_MCP_STATE_DIR=<каталог> npx -y avito-shopping-mcp setup   # один раз: пройти капчу
poetry run python main.py                                   # чат: вводи запросы, /exit — выход
```

Пример запроса: «найди зимнюю куртку до 5000 в Москве, в хорошем состоянии». Каждый запуск пишет построчный лог в `logs/`.

## Чего ожидать от агента

- Ищет **только одежду**; на остальные запросы вежливо отказывает и объясняет специализацию.
- Выдаёт топ-3–5 объявлений со ссылками и объяснением отбора; чего нет в объявлении — не выдумывает.
- При неполном запросе (нет размера, города или бюджета) задаёт уточняющие вопросы.
- Ответ не мгновенный: запросы к Авито идут с паузами, поиск и чтение карточек занимают десятки секунд.

## Ограниченный доступ к Авито

У Авито нет публичного API для покупателей: используемый [MCP-сервер](https://github.com/0xBADC0FFEE/avito-shopping-mcp) ходит на сайт через настоящий браузер с локальной сессией и работает только на чтение. Защита Авито может отвечать HTTP 439 (проверка браузера) или HTTP 429 (лимит на IP — пауза от 20 минут). При отклонённой сессии агент сам запускает пересоздание: откроется окно Chrome, в нём нужно пройти капчу. **Для лучшей работы отключи VPN** — запросы через VPN повышают шанс блокировки.
